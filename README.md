# Локальное хранилище проектов и знаний

Всё на этой машине: PostgreSQL с pgvector для векторов, ONNX-модель для
векторизации, MCP-сервер для доступа из Claude Code. Никаких внешних сервисов
и сетевых вызовов при поиске.

## Зачем

Единое место, куда складываются все проекты: код, документация, заметки,
конфиги. По ним можно искать — и смыслом, и точными словами — и получать
ответ с указанием, из какого файла он взят.

## Как устроено

```
проект → файл → фрагменты → вектора
                   ↓
              PostgreSQL
                   ↓
      поиск: вектора + слова → MCP → Claude Code
```

**Почему PostgreSQL, а не отдельная векторная база.** Метаданные, текст и
вектора лежат в одной транзакции и одном дампе. Отдельная векторная база
означала бы два хранилища, которые нужно согласовывать между собой и
резервировать отдельно, — ради задачи, где векторов десятки тысяч.

**Почему гибридный поиск.** Вектора понимают смысл, но путают похожие
идентификаторы: «pgvector 0.8.6» и «pgvector 0.7.0» для модели почти
одно и то же. Полнотекстовый поиск, наоборот, находит точные совпадения, но
не знает синонимов. Результаты объединяются по reciprocal rank fusion —
см. `rag/search.py`.

## Состав

| файл | что делает |
|------|------------|
| `sql/schema.sql` | схема: проекты, файлы, фрагменты, журнал индексаций |
| `sql/setup.sh` | создаёт роль, базу, расширение и файл подключения |
| `rag/chunker.py` | режет текст на перекрывающиеся фрагменты |
| `rag/embedder.py` | считает вектора моделью e5 |
| `rag/ingest.py` | индексирует проекты, инкрементально по sha256 |
| `rag/search.py` | гибридный поиск и соседние фрагменты |
| `rag/db.py` | подключение к базе |
| `mcpserver/knowledge_server.py` | MCP-сервер: 4 инструмента для модели |
| `run-server` | запуск MCP-сервера по stdio |
| `projects/` | по папке на проект |
| `tests/` | проверки чанкера |

## Команды

```bash
cd ~/projects/ai-farm

# индексация всех проектов / одного / предпросмотр
.venv/bin/python -m rag.ingest
.venv/bin/python -m rag.ingest rdp-mcp
.venv/bin/python -m rag.ingest --dry-run

# проверка подключения
.venv/bin/python -m rag.db

# проверки: чанкер и качество поиска на проиндексированном rdp-mcp
.venv/bin/python tests/test_chunker.py
.venv/bin/python tests/test_search.py
```

## Новый проект

```bash
mkdir -p ~/projects/ai-farm/projects/имя-проекта
cp ~/projects/ai-farm/projects/_template/project.toml ~/projects/ai-farm/projects/имя-проекта/
# положить файлы туда же
.venv/bin/python -m rag.ingest имя-проекта
```

Если проект уже лежит в другом месте — не копировать, а указать `path` в
`project.toml`. Подробности в `projects/README.md`.

## Модель

`intfloat/multilingual-e5-large`, 1024 измерения. Скачивается один раз в
`~/.cache/ai-workspace/models/multilingual-e5-large` (2.2 ГБ).

Модель обучена на префиксах: `query: ` для запросов и `passage: ` для
документов. Без них качество падает молча — ошибки не будет, просто поиск
станет хуже. В `rag/embedder.py` префиксы подставляются автоматически.

Требует ONNX Runtime, а не torch: на этой машине нет CUDA, и на CPU
ONNX Runtime быстрее и не тянет несколько гигабайт зависимостей.

Если менять модель — менять и `vector(1024)` в `sql/schema.sql`, и
`EMBEDDING_DIM` в `rag/embedder.py`, и переиндексировать всё заново
(`--force`).

## Подключение к Claude Code

MCP-сервер зарегистрирован в пользовательской области:

```bash
claude mcp list
claude mcp remove knowledge && claude mcp add -s user knowledge ~/projects/ai-farm/run-server
```

Инструменты: `search_knowledge`, `read_document`, `list_projects`,
`knowledge_stats`.

## Что осознанно не сделано

**Пароли в базе не хранятся.** В хранилище попадает только то, что лежит в
папках проектов, и оно не шифруется. Складывать туда учётные данные нельзя.

**Нет доступа к произвольным файлам на диске.** `read_document` читает только
то, что было проиндексировано, — это не обёртка над файловой системой.
